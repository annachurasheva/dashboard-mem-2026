# Дашборд dashboard-mem-2026

## О проекте

Это «кабина» владельца проекта «Мемориал 2026». Здесь собраны пошаговые инструкции (уроки) по работе с сайтом. 

Уроки объясняют полный маршрут: от добавления новых записей в базе данных до публикации изменений на публичном сайте.

## Схема маршрута

```
 ┌──────────────────────────────┐   pnpm build   ┌──────────────┐   перелив   ┌─────────────────────────────────┐
 │ memorial-korpech-crimea      │ ──────────────►│  dist/       │ ──────────►│ mem-2026                         │
 │ ветка qwen3-memorial         │                │ (готовый сайт)│            │ хостинг SC                       │
 │ (СТАРТ — наполнение: CSV,    │                └──────────────┘            │ https://mem-2026.sourcecraft.site│
 │  статьи, войсковые части)    │                                            │ (ФИНИШ — публичный дубликат)     │
 └──────────────────────────────┘                                           └─────────────────────────────────┘
```

**Как читать схему:**
1. **СТАРТ** — рабочий репозиторий `memorial-korpech-crimea` (ветка `qwen3-memorial`). Здесь вы добавляете новые статьи, обновляете CSV-таблицы с бойцами, редактируете тексты.
2. **Сборка** — команда `pnpm build` превращает исходники в готовый сайт (папка `dist/`).
3. **Перелив** — вы копируете содержимое `dist/` в репозиторий `mem-2026` и делаете коммит.
4. **ФИНИШ** — хостинг SourceCraft автоматически подхватывает изменения, и посетители видят обновлённый сайт.

## Оглавление уроков (`docs/lessons/`)

- **Урок 1.** Установка проекта на ПК (Git, Node 24.5.0, pnpm 10.33.0; клонирование, запуск dev-сервера)
- **Урок 2.** Добавление CSV-записей: статьи и войсковые части (где лежат файлы, как добавлять, какие скрипты запускать)
- **Урок 3.** Сборка нового `dist/` (что делает `pnpm build`, как проверить отсутствие ошибок, где появляется результат)
- **Урок 4.** Перелив `dist/` на портал SC (копирование, коммит, пуш; как убедиться, что SC подхватил изменения)

## Скелет дашборда (технические соглашения)

- Развивается **только на npm**: `package-lock.json` — источник истины.
- `pnpm-lock.yaml` здесь **не создаём** (блог живёт на pnpm 10.33.0).
- Node для обеих частей — **24.5.0** (`.nvmrc` в корне репо и здесь).
- `package-lock.json` собран на Node 24.5.0 / npm 11.x.

### Запуск дашборда (для разработчика)

```bash
npm install
npm run dev        # http://localhost:5180
npm run build
```

### Состав бандла (регламент экспорта)

- `src/main.tsx`, `tsconfig.json`, `vite.config.ts` — обязательный минимум
- `package.json` с `"engines": { "node": ">=22" }`
- `index.html`, `src/App.tsx` — заглушка под метрики блога
